# ADR 0004: shadcn new-york style migration

## Status

Superseded for visual ownership by [ADR 0005](0005-app-owned-presentation.md). The initial new-york appearance remains unchanged.

## Context

The shared design system in `@repo/ui` used the shadcn **radix-sera** preset: sharp corners (`rounded-none`), uppercase buttons, wide letter-spacing, and editorial typography. That reads distinctive but brutalist rather than polished SaaS dashboard.

Admin and marketing surfaces (`apps/admin`, `apps/web`) consume the same component package and should share one visual language.

Color tokens (blue-violet OKLCH primary on mist base) were already established and should not change.

## Decision

- Migrate `@repo/ui` from **radix-sera** to **new-york** via shadcn re-scaffold with `--overwrite`.
- Update consumer `components.json` files (`apps/admin`, `apps/web`) to `"style": "new-york"`.
- **Preserve** existing OKLCH CSS variables in `packages/ui/src/styles/globals.css` (colors unchanged).
- **Preserve** custom files not generated by shadcn: `theme-provider.tsx`, `theme-toggle.tsx`.
- Future shadcn component adds use the new-york preset.

## Consequences

- Large one-time diff across ~50 shared components; apps inherit softer rounded corners and title-case controls automatically.
- Re-scaffolding may require manual re-application of any hand-edited component customizations lost during overwrite.
- Reverting to radix-sera would require another full component re-scaffold.

## Alternatives considered

- **Token + targeted tweaks:** Bump `--radius` and patch uppercase/tracking in key components. Lower risk but leaves most components on radix-sera structure; rejected in favor of a clean preset switch.
- **App-only overrides:** Soften styles only in one app via local class overrides. Rejected — user chose all surfaces on one softened system.
- **Hybrid (sharp inputs, soft cards):** Rejected — inconsistent dialect within one package.
