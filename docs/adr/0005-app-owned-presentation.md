# ADR 0005: App-owned presentation

The public web and internal admin serve different audiences. Public website presets and client branding must be changeable entirely in `apps/web` without restyling admin. Each app therefore owns its styled primitives in `src/components/ui`, its tokens, font imports, theme rules and base styles in `src/index.css`, and its shadcn generation configuration. This supersedes ADR 0004's requirement for one shared visual language; both apps initially retain its new-york appearance.

Duplication of styled components is intentional. Copy improvements between apps when useful rather than coupling them through shared visual exports. Each app scans only its own source for Tailwind classes, and neither imports `@repo/ui` or the other app. Both theme providers accept a configurable `storageKey`, defaulting to the existing `baseplate-theme` identity to preserve preferences. Browser preferences load after hydration so the server and initial client markup agree. Set distinct keys when surfaces share an origin but should remember independent preferences.

The monorepo, shared tooling, and `@repo/types` DTO contracts remain shared. Utilities or behavior may be shared where useful, provided this does not impose presentation. The currently unused `packages/ui` catalog is retained to avoid deleting unrelated starter components; it is not an active design dependency. Copy a desired primitive into the consuming app or generate it there rather than importing that catalog. Run shadcn from the target app so both generated components and token edits stay local. Public web continues to use TanStack Start SSR and its existing SEO route metadata.
